# Bounded GLSL ES adversarial corpus (W1)

`tools/shader_fuzz.py` extends the predecessor compiler harness, not the GPU renderer.
It imports `tools/validate_shaders.py:expected_result` and uses the existing
`benchmarks/reducer/reduce.py:minimize` for optional mismatch reduction.

## Corpus and proof domain

89 stable cases, 66 expected accepts and 23 expected rejections:

- 60 unique, valid fragment programs: ESSL 300/310/320 × scalar, vector,
  function, std140 UBO, sampler expression contexts × four transformations.
- 18 invalid type, absent precision, sampler coordinate type, unsupported required
  extension, negative array extent and linked varying type cases.
- 9 compute/SSBO/image/shared atomic cases, rejected at 300 and accepted at 310/320.
- 2 excessive local-size cases, explicitly relative to glslang's built-in resource
  profile. This is not a portable claim about every GPU's static limits.

The generator uses a deliberately small typed expression AST (`Literal`, `Add`)
inside structured stage/declaration/function productions. It is not a GLSL parser
and does not mutate arbitrary source text. Seed changes bounded literal values;
the 60 combinations are structurally distinct contexts/transformations, not 60
renamed copies. The four transformations are identity, exact constant folding,
fresh local binding and insertion of an unreachable branch. Operands are integers
1–8 and sums 2–16, exactly representable in highp float; no reassociation, NaN,
side effects, texture-call movement, or undefined evaluation is introduced.
The baseline and transformed expression retain every resource operation.
No layout permutation or general input reordering is claimed without a proof.

`shaders/` is the checked-in seed-0 corpus. Unit tests compare generated bytes to
these files, check uniqueness and all bounds. The sampler and UBO shaders only
compile here: no bindings, pixel equivalence or rendering is asserted. The atomic
shader uses one invocation and initialized shared storage. No workload is dispatched.

## Reproduce

```sh
python -m unittest discover -s benchmarks/fuzz -v
GLSLANG_VALIDATOR=/path/to/glslangValidator python -m unittest discover -s benchmarks/fuzz -v
python tools/shader_fuzz.py --compiler /path/to/glslangValidator --output reports/fuzz --budget 90
python tools/shader_fuzz.py --case 300-invalid-varying --output reports/replay
python tools/shader_fuzz.py --seed 0 --emit-only --output reports/generated
```

The report contains an argv replay command per case, source hashes, exact command,
exit code and bounded compiler logs. Sources are retained beside the report.
`--reduce` uses the predecessor line ddmin for unexpected valid-shader rejection,
preserving the exact first compiler diagnostic and original version directive.
It does not reduce links, successful unexpected acceptance, timeouts or crashes.
The reducer reports whether it actually established 1-minimality. Full case replay
remains available for all failures; no crash is relabeled as an expected rejection.

## Isolation and evidence

Every compiler invocation has a separate process group, wall-clock deadline,
RLIMIT_CPU, RLIMIT_AS, RLIMIT_FSIZE and disabled core dumps. Every exit, including normal success and failure, kills the process group and
reaps its leader, so ordinary grandchildren cannot outlive a completed test. Output is file-backed and capped at 64 KiB, rather
than accumulated unboundedly in memory. Defaults: 3 seconds/case, 90 seconds/run,
512 MiB address space, 16 KiB/shader; CLI limits cannot exceed 30 seconds/case,
600 seconds/run, 2 GiB address space and 64 KiB/shader. No shell or generated code
execution. Requires POSIX quotas; other platforms explicitly report UNSUPPORTED.
These process limits are not a hostile-code security sandbox. The trusted compiler
is supplied by the operator, never downloaded or executed from corpus content.

Statuses distinguish PASS, EXPECTED_ERROR, MISMATCH, COMPILER_FAILURE,
TEST_TIMEOUT, RESOURCE_LIMIT, HARNESS_FAILURE, UNSUPPORTED, BUDGET_EXHAUSTED and
BLOCKED_BY_TOOLCHAIN. CPU/log quota signals are resource limits, not driver bugs.
No test result is classified as GPU performance degradation. Null device,
extensions and output_image fields honestly record that this backend never opens
GLES. Compiler version/binary hash and all logs are retained in report.json.
Reports also include Markdown summaries and conform to report.schema.json.

The checked evidence is **standalone glslang compile/link**, not Mesa, ANGLE,
Android, physical-driver execution, GPU crash testing, output equivalence, or
performance evidence. W5 must provide those independent comparisons. These
bounded authored grammars do not constitute comprehensive GLSL fuzz coverage.
