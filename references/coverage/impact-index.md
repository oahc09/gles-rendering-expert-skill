The fixed index covers exactly the current source-ledger's four candidate records and runtime-links' eight receipts. Candidates link their cited source-review evidence to candidate and declared rule/example/test targets; runtime collector/report files feed their receipt. This is declared provenance, not automatically inferred code dependency. Four null rule links remain UNLINKED; questionable historic candidate example/test associations are preserved for review, not silently “fixed” or adopted.

Every path and base SHA is frozen. Changed existing content is a legitimate CHANGE_REVIEW_REQUIRED input and propagates to downstream targets; malformed hash, path escape, unknown/omitted nodes or subjects, orphan/cyclic/omitted edges and unknown test IDs fail INCOMPLETE. Changed SHA is never silently rebaselined. Source-ledger structural mapping changes require explicit index maintenance and review rather than opportunistically generating new dependencies. Existing lifecycle.validate handles provenance, conflict and expiry checks; its validation failure remains INCOMPLETE governance and review-required. No automatic winner or adoption.

Two closed validation IDs, ledger-lifecycle and runtime-links, are recommendations only. They map to existing validators, not executable commands supplied by input. The tool never runs commands, fetches sources, schedules tasks, modifies old historical change-impact.json, or upgrades candidate states. SNAPSHOT_UNCHANGED means identical tracked snapshot, **not** no verified substantive upstream change. Complete corpus review, independent review, hardware/provider and release remain outside this closure. Source/report hash consistency is not trusted remote attestation.

Regression validation IDs are selected by affected candidate/runtime subjects rather than both unconditionally.
