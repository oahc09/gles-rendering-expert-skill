# W4: bounded EXT_disjoint_timer_query runtime semantics

Primary source: [Khronos EXT_disjoint_timer_query rev9](https://raw.githubusercontent.com/KhronosGroup/OpenGL-Registry/1cdd228e34966dd6b95bd203e9f84faba0f371a1/extensions/EXT/EXT_disjoint_timer_query.txt).

AI review mapped state query / Errors sections to `benchmarks/coverage/timer-query/run.py`: generated names become query objects upon first use; CURRENT_QUERY matches active elapsed object; querying active object is INVALID_OPERATION; nested elapsed, counter on active id, inactive End and zero Begin all INVALID_OPERATION; counter wrong target INVALID_ENUM. QUERY_COUNTER_BITS may legally be zero, otherwise timer minimum is 30. This experiment restricts acceptance to 64-bit counters; legal narrower widths fall back pending an overflow bound, because overflowed elapsed results are undefined. Results use unsigned 64-bit EXT entrypoint, nanosecond units per spec, but no values are retained or compared to CPU time. Result availability is checked before reading, then after; query objects are deleted before context teardown.

Disjoint before/after reads reject compromised/unknown observations. Forced disjoint test is simulation only. Actual Mesa/ANGLE software evidence and forced-disable clear/readback are in the experiment directory. The latter does not prove physical unsupported behavior. No device performance validation, gain, context-reset recovery, long-lived wraparound guarantee, or full asynchronous scheduler is claimed. Both timestamp and elapsed semantics are exercised only in a short finite task; never equate their differences.
