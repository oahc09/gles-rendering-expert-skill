# v1.0.4 capability-based engineering paths

| Technique | Gate and actual sample | Correctness / fallback | Measured status |
|---|---|---|---|
| Compute + draw / GPU-driven generation | GLES3.1 / ESSL310, SSBO and indirect limits; S07 actual compute SSBO and indirect draw | Consumer-specific storage/command/vertex barriers; fixed-seed image golden; CPU-generated vertices if compute absent | Software EGL only; device timing unmeasured |
| Skinning + streaming | GLES3 UBO alignment, uniform limits and instanced draws; S06 | Pose golden; CPU skinning/chunking when block budget exceeded | Software EGL only |
| Local postprocess fusion | FBO format/renderability probe; S02/S04 | Compare image error before fewer passes; S04 skip-blur control is intentionally rejected, not counted as an optimization success | Software correctness; RT traffic unmeasured |
| Low precision | Query fragment precision ranges; S02/S04 arithmetic and RGBA16F probe | Error tolerance and fallback to highp/RGBA8 or full precision; mediump is not a general performance guarantee | Query + software golden; mobile precision/perf unmeasured |
| Texture assets | Probe supported compression/format/filter/render-target separately; S01 dynamic upload | Fixed unpack alignment/stride, legal upload tuple, mip completeness; uncompressed RGBA8 fallback | Host upload correctness; asset-size/physical bandwidth not measured |
| Android wallpaper / multi-surface | Android APIs, per-Engine ownership and visibility; `examples/android_cases/` | Lifecycle-bound rendering, destroy/recreate surface separately from context, SDR fallback | Java/NDK compiler evidence separate; device acceptance NOT_RUN |
| External texture / HDR / pacing | Extension token + pointer + actual image-import/display probe, not API level alone | CPU copy only if content readable; reject protected unsupported path; explicit SDR; Choreographer/presentation policies | Android target acceptance NOT_RUN |

## Backend decision tree

1. Probe the current GLES version, limits, precise extension tokens and runtime format/import outcomes. Headers and OS names do not prove support.
2. If required GLES features exist, keep native GLES as a correctness baseline. On an authorized device with installed ANGLE Vulkan, capture its exact backend creation and compare the same workload; do not choose by GPU-name substring.
3. If ANGLE does not satisfy limits or regresses compatibility, fall back to the verified native path and retain the failure evidence. Unsupported device settings remain unchanged.
4. Vulkan-only ray tracing, mesh shaders, bindless assumptions or vendor neural features do not become GLES core. A separate Vulkan implementation is a project decision, not a fallback emitted as GLES code.
5. No hardware evidence means hypothesis / NOT_RUN. A lower CPU wall time including compilation/readback on llvmpipe is not a mobile GPU improvement.

Primary contracts: [GLES3.1 memory barriers](https://registry.khronos.org/OpenGL-Refpages/es3.1/html/glMemoryBarrier.xhtml), [Android AHardwareBuffer](https://developer.android.com/ndk/reference/group/a-hardware-buffer), [ANGLE Android setup](https://github.com/google/angle/blob/main/doc/DevSetupAndroid.md).
