## Review corrections

- S07's deliberate indirect-buffer mutation now uses BUFFER_UPDATE_BARRIER_BIT before API-side overwrite of compute-written storage; software success alone would not expose this portability race.
- Wallpaper surface destruction waits for its render owner to cancel frame callbacks and release the surface, including owner-exit and interruption handling; static contract tests are not Android runtime proof.
- Repair reproduction now freshly builds/runs scenes and checks source/runner/binary/image identity, rather than trusting historical JSON verdicts.

## Android follow-up after the first Draft PR checkpoint

The initial candidate omitted explicit AHardwareBuffer import and configured HDR
output. Missing devices were not a reason to leave feasible source implementation
unfinished. The follow-up adds a CPU-produced RGBA8 AHardwareBuffer JNI/EGLImage
path with synchronous ownership, actual device-time pixel verification and external
texture fallback; and a wallpaper BT.2020/PQ RGB10A2 surface path with exact display,
extension, configuration and queried surface/attachment checks plus SDR fallback.
Multiple wallpaper Engines now lease the shared EGLDisplay, so one Engine's PQ
fallback cannot terminate a cooperating Engine's display. Distinct contexts remain
independently owned.

Actual local follow-up evidence (`evidence/android-followup/`):
- Seven Java sources compiled against official Android API35 with Java17 language/API target.
- API26 arm64 strict native compile/link: AHB JNI library, existing validation harness and six legacy examples; ELF identity and native/shared-runtime LOAD alignment checked.
- Three embedded shader pairs actually compiled/linked.
- Eighteen HDR policy and fourteen shared-resource lifecycle/concurrency assertions executed on the host JVM; these do not execute Android/EGL.
- Twenty-one common source/compiler infrastructure tests, six HDR source/math checks and twenty-one release/shader infrastructure tests passed.
- Actual Gradle APK assembly attempted but blocked resolving AGP8.7.3: the Java network path to the configured proxy reports `Network is unreachable`, including an IPv4 diagnostic. No proxy bypass, new environment, license acceptance or Actions run was used.

The original no-toolchain observations are historical. Java compilation and target
ELF linking now have real evidence, but APK packaging, Android lifecycle/import
execution, physical HDR and per-device goldens remain unverified. The minimal PQ
path deliberately does not claim full HDR10 mastering metadata, P3/HLG modes,
external asynchronous producer-fence interoperability or camera/Vulkan zero-copy
performance. Both release gates still reject release; metadata remains 1.0.2.
