## 1. v1.0.4 核心定位

在 v1.0.3 “规则准确、可构建、可评测”的基础上，升级为“基于 **真实平台能力**、**完整渲染场景**、**GPU trace/counters** 的 AI 诊断、优化和闭环验证”。不扩张为泛 Vulkan Skill；Vulkan/ANGLE 作为 GLES 的底层兼容性与迁移决策场景。

必须交付的三个成果：
1. **Device Capability & Regression Lab**：原生 GLES/ANGLE Vulkan backend 对照，设备能力/驱动指纹，正确性与兼容性报告。
2. **Scene-level GPU Benchmark**：至少 8 个有视觉 golden 和 CPU/GPU/带宽采集协议的真实负载，含优化收益与退化案例。
3. **Evidence-based Agent Repair**：针对异常 trace 或源码给出可追踪规则、最小补丁及前后差异；无法获取设备计数器时不宣称性能收益。

## 3. 工作包与验收

### W0 — 基线/未完成门禁（阻塞）

- 获取 `main` SHA、tags、已有 PR、已合并修改、未关闭 Issue、release gate 的真实状态；核查本地差异，不覆盖用户变更。
- 运行 v1.0.3 现有检查命令，区分 local / CI / Android device / live model / real GPU 五类结果。
- 明确 v1.0.3 是“工程代码完成”还是“完整发布验收”；形成 `docs/v1.0.3-closure.md`，列 unresolved/accepted-limitation/owner/evidence。
- **DoD**：当前状态有证据、门禁无虚假 PASS，升级分支从明确的 main SHA 建立。

### W1 — Device Capability & GLES/ANGLE 双驱动实验室

- 在 Android 建立 `GL_VENDOR/GL_RENDERER/GL_VERSION/GLSL_VERSION`、EGL 版本及扩展、纹理格式/精度/限制、支持的 EGLImage/AHardwareBuffer/同步能力快照。
- 在允许且可测的设备上对照 native GLES 与 ANGLE Vulkan backend：启动、context/surface 生命周期、FBO、MSAA、sRGB/HDR、program binary、external texture、跨上下文可见性、渲染正确性和驱动 crash。
- 区分 GL 原生驱动、ANGLE、软件渲染；添加 backend fallback 和 fingerprint 日志，禁止用 substring 猜测 GPU 功能；用 extension entry point 和 runtime feature probe。
- 支持 Windows ANGLE 和 Embedded Linux GBM/EGL 的共享能力快照格式；真机没有则显式 NOT_RUN。
- **DoD**：至少 2 种 backend 取得真实可重复正确性报告；若硬件缺失，工具完成但标 BLOCKED_BY_HARDWARE，不冒充通过。

### W2 — 移动 GPU 渲染微架构与风险规则深化

- 建立 Mali/Immortalis、Adreno、PowerVR/IMG、Vivante/etnaviv 的 vendor adapter + 证据级别；已有旧规则只增量纠错，不删除合法场景。
- TBDR tile load/store、GMEM、LRZ、HSR、tile memory budget、depth prepass、MSAA、framebuffer fetch/PLS、纹理带宽、blend/overdraw、render-target switch 分别写出正例/反例/可测 counter。
- 不使用跨设备无条件的“永远更快”；性能记录受 GPU、driver、热状态、分辨率、backend 约束。
- **DoD**：每条厂商性能主张都有前置条件、相关性能指标与至少一个使该建议不成立的对照假设。

### W3 — 场景级 Benchmark（重点）

建立至少 8 个独立场景；复用现有样例并组合为业务规模的完整 workload：

| 场景 | 压测维度 | 关键验收 |
|---|---|---|
| S01 2D 透明卡片/动态壁纸 | alpha blend、overdraw、频繁小区域更新 | visual golden + blend/overdraw trace |
| S02 水体与折射/焦散 | multipass、normal/depth reuse、half precision | 图像差分、GPU time、RT bandwidth |
| S03 粒子与软粒子 | instancing、buffer upload、depth sampling | CPU submit、fragment、峰值流量 |
| S04 HDR bloom / tone mapping | 多级 FBO、sRGB/WCG、半精度 RT | 色彩误差、RT traffic、pass cost |
| S05 MSAA + depth/stencil | tile resolve、invalidate、depth prepass | 含/不含优化对照及适用条件 |
| S06 GPU skinning + instancing | 顶点吞吐、UBO/SSBO、buffer streaming | 动画正确性 + vertex/CPU load |
| S07 Compute + draw 共享数据 | GLES 3.1+ barriers、SSBO、indirect | 同步正确性及并行收益/退化 |
| S08 大规模透明 Gaussian/叠加层 | overdraw、混合精度、LOD / background merge | 视觉误差、覆盖面积、GPU time |

所有场景可重复、具有固定随机种子和显式工作负载规模；性能数据必须关联实际 device/build/driver，软件 Mesa 只做正确性基线。保留优化失败样本。禁止预设 FPS 改善百分比。

**DoD**：8 个场景源码、可运行说明、视觉 golden、参数 sweep、基线/对照策略完整；至少 2 个真实设备/驱动配置的性能报告作为建议目标，如资源不足应如实标记而非填假数据。

### W4 — Trace 解析与 GPU 问题定位

- 定义规范化 `trace-manifest.json`：来源（Perfetto/AGI/RenderDoc/Streamline/厂商 SDK）、设备、GPU、驱动、时间范围、counter 单位、sample/aggregation method、raw artifact hash、缺失项。
- 先对可公开、许可允许的导出 CSV/JSON/Perfetto 数据做解析；RenderDoc 不必从 proprietary capture 中逆向读取，工具不可用时报告 unsupported。
- 识别：CPU submit-bound、GPU fragment-bound、tiler/geometry-bound、bandwidth-bound、sync stalls、shader compile hitch、thermal/power drift、swap backpressure。
- 输出明确的“证据、假设、还需要的计数器、最小验证 A/B、回退条件”，不从 GPU 利用率一个指标断言瓶颈。
- **DoD**：至少 12 个带 ground truth 的 trace fixtures，负样本/缺失数据必须触发保守诊断；每次推断可追溯原始记录。

### W5 — 高价值技术扩展

- GLES 3.1 compute + render pipeline（barrier / SSBO / image load-store）、GPU-driven culling、局部后处理 pass 融合、低精度数值误差与纹理资产管线。
- Android 交互壁纸、Surface 多实例、AHardwareBuffer/外部纹理、HDR/WCG、帧节奏与上下文恢复做 2 个端到端工程案例，突出 Android 生命周期和真实业务约束。
- 增设 GLES 与 Vulkan/ANGLE 之间的 capability-based decision tree，但不把 Vulkan-only 特性误写为 GLES Core 功能。
- **DoD**：每项提供 capability gate、真实源代码/可构建样例、正确性 golden、fallback、已测和未测状态。

### W6 — Agent Diagnose → Patch → Validate 工作流

- 在现有 64 案例 Benchmark 上增量增加至少 24 条以真实失败/修复为中心的案例（目标），同时保留 v1.0.3 评分口径用于纵向比较。
- 输入：代码片段 + 运行日志/trace + capability snapshot。输出：证据链、root cause 分级、最小 diff、编译/回归命令、预期/实际 GPU 改善。
- 对照 no-skill vs with-skill 的真实 provider 运行；明确 `BLOCKED_BY_PROVIDER` 状态，不把 synthetic cases 当真实模型表现。
- 指标：正确 API 使用率、合法代码误报率、编译/运行成功率、root-cause 命中、修复回归率、无依据的性能声明比率；每个指标保留分母和失败原始样本。
- **DoD**：回归不低于 v1.0.3 现有可靠规则；新增案例通过独立审查和可复现运行。

### W7 — CI、文档与 v1.0.4 发布

- 优先复用 `tools/validate_rules.py`、`tools/validate_shaders.py`、`benchmarks/agent/`、`tools/check_release_gates.py` 和 workflow，不创建新的并行体系。
- PR CI 对 lint/schema/规则测试/GLSL 编译/host EGL correctness 设强制门禁；耗时或硬件相关测试独立设备 job，结果清楚标为 optional/manual/required。
- 保存版本间对比报告、设备覆盖情况、trace fixture 校验报告、研究证据 ledger、未完成项及风险接受记录。
- 保留 `SKILL.md` 已有触发条件和平台约束；只有正式 release gates 全满足或显式批准风险接受且文档同步后，再升级元数据与 tag。
- **DoD**：单一 `v1.0.4` 发布，README/CHANGELOG/tag/证据一致；不得宣称未执行的设备测量和 live agent 数据。

## 5. 建议验收矩阵

- 原有 112 合约案例、16 ESSL 检查、主机 EGL 和 64 Agent 案例保持兼容。
- v1.0.4 新增 8 个场景、12 个 trace fixtures、24 个 Agent case（均为计划目标，不是已完成数量）。
- Android native GLES vs ANGLE 至少一个同机对照；真实 Mali/Adreno/PowerVR 尽可能覆盖三类 GPU，实际无法获取则记录覆盖缺口。
- 图像 golden 允许事先明确的色彩空间与数值容差；不能将驱动输出图像 bit-exact 作为所有设备的通用前提。
- 测量包含 p50/p95 frame time、CPU/GPU timing、必要 bandwidth/counters、热/功耗条件、driver、OS、分辨率、重复运行次数；统计应展示离散度。
