## 2. 开发工作包

### W0 基线审计与前序版本差异（必需）

**实施**：读取 HEAD、tag、未合并 PR、`SKILL.md`、现有 `benchmarks/`、`references/`、`examples/`、`docs/*release-gates*`，对 v1.0.3–v1.0.6 的实现/未验证/缺失进行矩阵归类；避免覆盖现有模型路由或触发条件。

**交付**：`docs/v1.0.7-baseline-and-gap.md`；前序能力复用/缺口/证据清单。

**验收**：每项功能状态必须是 `EXISTS_VERIFIED` / `EXISTS_UNVERIFIED` / `MISSING`，附文件路径与可复现命令；任何提交前再次检查差异。

### W1 Shader Variant 与离线构建策略

- 构建 `Feature × GLES Version × Extension × Quality Tier` 的变体约束模型；支持互斥条件、非法组合拒绝、生成与裁剪预算。
- 缓存 key 必须包含源码/宏、编译选项、GL_VENDOR/RENDERER/VERSION、驱动信息、扩展快照；缓存命中必须有错误回退和格式兼容检查。
- 区分 GLES `glGetProgramBinary` 可用性、运行时编译/链接、以及 glslang 的静态检查能力；不宣称离线编译的二进制在不同驱动上可移植。
- 产出 3.0 / 3.1 / 3.2 正负变体、低端 fallback，以及缓存无效化案例。

**交付**：`references/pipeline/shader-variants.md`、可机器读取的 variant schema、validation scripts、至少 12 条正负样例。

**验收**：非法 GLES 版本或未探测扩展的变体被拒绝；正常组合真实编译与链接；驱动/源码变化引发缓存失效；回退后可运行。

### W2 Material ABI 与 Descriptor Binding 验证

- 建立 Material Parameter Contract：uniform block/std140、SSBO/std430（仅适用版本）、sampler、纹理格式、layout/location/binding、array 和 shader interface。
- 为不同 GLES 核心版本明确可用接口与 fallback；不得将 Vulkan Descriptor Set 当成 GLES Core。
- 编写 C++17 对应布局断言、`glGetActiveUniformBlockiv`/反射检查、纹理 unit 与 sampler 冲突诊断。
- 兼容现有示例 API，不直接修改引擎对外接口。

**交付**：`references/pipeline/material-abi.md`、binding manifest、至少 12 条正负样例、一个 PBR/透明材质的真实绑定示例。

**验收**：跨 Shader 变体的 ABI 不兼容必须被发现；错误绑定可定位到参数名、资源位置和版本要求。

### W3 RenderGraph 规划与 FBO 附件生命周期

- 给出一个**独立可运行的最小 RenderGraph 规划器/验证器**（不要强迫业务引擎迁移）；Pass 描述读写 Attachment、格式、尺寸、采样数、生命周期。
- 检测循环依赖、读前写、同一资源未定义内容读取、Attachment 格式不匹配、多采样 resolve 错误、跨 Pass 依赖和缺少 invalidate 的风险。
- 在不改变渲染结果的前提下建议 transient attachment、别名复用、FBO 切换减少、MSAA resolve 合并；并以真机数据证明收益。
- GLES 不具 Vulkan 的显式 RenderPass/Subpass API；把规划层的“pass”与驱动真实行为分开标注。

**交付**：`references/pipeline/rendergraph-gles.md`、JSON schema、可运行 graph checker、至少 10 个 graph 用例。

**验收**：合法拓扑可得到执行顺序；非法依赖输出路径和规则 ID；正确性有 golden 与 GLES 运行测试。

### W4 资源 Hazard 与同步检查

- 覆盖 SSBO/Image/Texture/Framebuffer 的跨阶段访问；`glMemoryBarrier` 位与读写模式；跨上下文 fence/flush/wait；未定义反馈循环。
- 明确哪些 hazard 可通过静态 graph 检查，哪些依赖动态 GL 状态与扩展能力；保守报告不等于真实驱动 bug。
- 提供 3.0 非 Compute 路径、3.1 Compute 路径和 3.2 可用扩展路径。

**交付**：`references/pipeline/resource-hazards.md`、至少 12 条 hazard 正负案例。

**验收**：能区分真正缺少同步与保守警告，报告所需 barrier、受影响阶段、复现实验，不误把 Vulkan barrier 语法写成 GLES。

### W5 材质与颜色管线的正确性

- 输入贴图 color space、linear-space lighting、sRGB FBO、alpha/premultiplication、HDR/tone mapping、格式量化、MSAA blending 的业务级端到端测试。
- 显示侧校色测试必须区分软件截图、GPU 写出值与真实屏幕观感；保留数值容差与误差来源。
- 强化大范围渐变、透明多层、粒子、玻璃和 PBR 材质的视觉回归；与 v1.0.5 的 Golden Image 基础复用而非重新开发。

**交付**：至少 6 个有 reference image 的场景和色彩空间比较用例；跨 backend 的差异分析报告模板。

**验收**：正确区分设计上允许的画质差异和回归；sRGB/linear、alpha 和 FP16 量化有针对性阈值，不能对所有平台使用同一像素绝对误差阈值。

### W6 Shader 性能分析与静态风险提示

- 识别动态纹理采样、巨大变体、非一致分支、纹理高频访问、冗余 MRT 写出、寄存器/占用风险。
- 静态分析只给风险和假设，**不宣称已测得 GPU 性能改善**；采集真机 GPU time、bandwidth 和热状态并对照。
- 复用 W1 编译结果与 v1.0.4/1.0.5 Trace 适配器。

**交付**：Shader 风险报告 schema、至少 8 个可重复实验，其中包含无收益/性能退化反例。

**验收**：风险项追溯到 shader、stage、行号、设备条件及可验证的 A/B 实验；未取得真机数据则标 `NOT_RUN`。

### W7 管线错误诊断 Playbook

覆盖：Variant 宏分歧、程序缓存失效、Material ABI 冲突、FBO feedback、Barrier 漏失、错误 MSAA Resolve、颜色空间重复转换、透明边缘暗边、HDR 截断、Shader 编译启动卡顿。

**交付**：至少 10 个 `symptom → capture → minimal reproduction → root cause → fix → regression` 案例，优先复用 v1.0.6 的 minimizer。

**验收**：案例可在隔离环境重现或明确标示硬件依赖，不能以猜测代替证据。

### W8 Agent Benchmark 3.0：完整管线开发

- 任务至少覆盖 Generate、Review、Diagnose、Optimize 四类，新增 >= 30 个**独立**场景案例，避免与旧用例重复。
- 比较 no-skill/with-skill 的 API 合法性、代码编译、数值/画质正确性、误报率、首次运行成功率、诊断证据完整度。
- 完整任务示例：粒子 + Bloom + Tonemap、多材质透明、离屏 MSAA、相机外部纹理混合 3D、计算结果用于绘制。

**交付**：标注数据、runner 增量、双盲评判指南、失败案例和结果报告。

**验收**：真实模型未运行不能把 fixtures 结果宣称为模型能力提升；保留原始输出、成本/耗时和 CI 记录。

### W9 90 天技术雷达、CI 与统一版本发布

- 扩展现有 radar，而非新建互不兼容的第二套：每周增量抓取、每月回顾 90 天、按 source/commit/release ID 去重、X 人工验证。
- 每项已接受技术都产生 `source → rule/card → example → test` 追溯链；未验实的技术进入 candidate 队列。
- 现有 CI 增加 schema 校验、shader 编译/链接、C++17/EGL smoke、RenderGraph 负例、Material ABI、Agent runner 单元测试；真机任务独立上报。
- 仅当已有各版本的发布策略与 v1.0.7 门禁核准时才更新版本元数据、tag、release；不绕过未通过的门禁。

**交付**：研究归档、`docs/v1.0.7-traceability.md`、`docs/v1.0.7-release-gates.json`、CHANGELOG、PR 汇总、最终报告。
